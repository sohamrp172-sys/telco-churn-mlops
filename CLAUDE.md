# CLAUDE.md

This file guides AI assistants working on this repository.

## Project Overview

Telco Customer Churn MLOps pipeline. Predicts customer churn using scikit-learn models.
Full MLOps stack: DVC (data versioning), MLflow (experiment tracking),
GitHub Actions (CI/CD), Docker (containerization), FastAPI (serving).

## Project Structure

- `data/raw/` — DVC-tracked raw CSVs (telco_v1, v2, v3); never commit large CSVs directly
- `data/processed/` — Output of the preprocessing stage; generated by `src/preprocess.py`
- `models/` — Trained model artifacts (.pkl); DVC-tracked, never commit pkl files directly
- `src/` — Core pipeline scripts: preprocess, train, evaluate
- `api/` — FastAPI application for serving churn predictions
- `tests/` — pytest test suite for pipeline and API
- `.github/workflows/` — GitHub Actions CI/CD configuration

## Commands

```bash
# Preprocess
python src/preprocess.py --input data/raw/telco_v1.csv --output data/processed/telco_processed.csv

# Train
python src/train.py --input data/processed/telco_processed.csv --model-type rf --run-name <name>

# Evaluate
python src/evaluate.py --model-path models/churn_model.pkl --input data/processed/telco_processed.csv

# Full DVC pipeline
dvc repro

# Run tests
pytest tests/ -v

# Start API
uvicorn api.main:app --reload

# MLflow UI (available at localhost:5000)
mlflow ui
```

## Git Rules

- Conventional commits only: `feat:`, `fix:`, `ci:`, `docs:`, `refactor:`
- No co-author lines. No AI attribution in commits.
- Always commit `dvc.lock` when `dvc repro` is run.
- Tag after each successful training run: `v1.0`, `v1.1`, `v1.2`

## MLflow Convention

- Experiment name: `churn-prediction`
- Run naming: `v{batch}-{model-type}` — e.g. `v1-logistic`, `v2-logistic`, `v3-random-forest`

## DVC Convention

- Remote: Google Drive
- Always run `dvc push` after `dvc repro`
- `data/raw/` and `models/` are DVC-tracked; never commit pkl files or large CSVs directly to git

## Code Style

- No sklearn pipelines — use plain pandas for all preprocessing
- `argparse` for all CLI scripts
- `joblib` for model serialization
- All scripts must be runnable standalone from the project root
